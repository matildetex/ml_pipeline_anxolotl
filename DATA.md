# DATA.md — Datasets used by this pipeline

None of the raw datasets are committed to this repository (see `.gitignore`) —
they are too large and/or contain participant data. This document explains
what each one is, how to obtain it, and where the code expects it to live.

## 1. Anxolotl (own study — private, not publicly redistributable)

The Anxolotl dataset was collected for this thesis: Apple Watch recordings
(heart rate, interbeat interval, accelerometer) plus, for a subset of
sessions, reference-grade Biopac ECG and PASAT task results, during a
protocol with a rest baseline and three stress-induction blocks.

| Component | Expected path | Contents |
|---|---|---|
| Apple Watch sessions | `sessions/session_0006.csv` … `session_0044.csv` | 39 files, columns `timestamp_unix,hr_bpm,ibi_ms,steps,calories_kcal,distance_m,acc_x,acc_y,acc_z` |
| Biopac + PASAT reference data | `dataset.zip` | 59 session folders `dataset/sessions/real_idNN_<timestamp>/`, each with a `biopac/*.acq` file and a `pasat_results.json` |

**Access:** this is participant data collected under an informed-consent
protocol; it is **not** publicly downloadable. If you are a collaborator who
should have access, obtain the files from the author directly rather than
from any public link.

**Note on participant counts:** `sessions/` has 39 Apple Watch CSVs while
`dataset.zip` has 59 Biopac session folders — the two collections are not
1:1 (some sessions have Biopac reference data but no matching watch export,
or vice versa). Cross-check session IDs directly (`ls sessions/` vs. the
`real_idNN_*` folder names inside `dataset.zip`) before assuming a session id
exists in both — there is no single indexed manifest of the overlap in this
repo.

**Public partial release:** an anonymised copy of the Apple Watch signals
(downsampled, timestamps stripped, phase markers heuristically re-derived —
no questionnaire data) is being prepared for a future Zenodo release. A link
will be added here once it is published.

## 2. WESAD (public)

Schmidt, P., Reiss, A., Duerichen, R., Marberger, C., & Van Laerhoven, K.
(2018). *Introducing WESAD, a multimodal dataset for wearable stress and
affect detection.* ICMI 2018.

**Access:** WESAD is publicly released by the original authors (Uni Siegen).
Search for "WESAD dataset Schmidt 2018 download" or check the official
project page — **verify the current URL yourself**, as we are not certain it
is still hosted at the same address used when this repo was built.

**Placement:** download the archive and place/rename it as `wesad.zip` at
the repo root. `1_wesad/wesad_preprocessing.py` reads directly from this zip
(`S2/…/S17` subject folders, each `S*.pkl` + `S*_E4_Data/` + `S*_quest.csv`)
— no manual extraction needed. Uncompressed size is ~16.4 GiB.

### WESAD feature schemas — old and new, used deliberately in different sections

WESAD was processed into two different feature sets over the life of this
project. **The thesis deliberately uses both, in different sections.**

| Schema | Stats per channel | Used in the thesis at |
|---|---|---|
| Old | 8 | §4.2, §4.4 (training space) |
| New | 11 | §4.3, §4.4 (Table 4.12's evaluation target), §4.13 |

- Old schema: frozen snapshot,
  `processed_data/wesad_archive/processed_data_137feat_snapshot.pkl`.
- New schema: regenerated by `1_wesad/wesad_preprocessing.py`.

**To reproduce a thesis number:** §4.2 / §4.4's training space → use the
137-feat snapshot above. §4.3 / §4.13 → use the current
`wesad_preprocessing.py` output, filtered to the 5 channels `acc_wrist,
hr, ibi, rmssd, sdnn`.

To find which script produced a specific table's numbers, check
`results_master.csv`'s `source_file` column.

Full technical detail — exact feature/channel counts, unused byproduct
configs, why §4.4 also uses a 55-feature evaluation target alongside its
40-feature training space, and the canonical source per model for Tables
4.5/4.9 — is in the internal audit log (not part of this public repo).

### `2_cross_dataset/` — canonical Table 4.12 source, pre-fix scripts archived

Canonical source for **Table 4.12** (cross-dataset, §4.4 evaluation target)
is `2_cross_dataset/wdd_vs_anxolotl_et_vs_ensemble_wilcoxon.py` — 686-window,
leak-fixed Anxolotl target, 55 features, RF/ET/Ensemble RF+ET + a
per-subject Wilcoxon significance test. It imports Anxolotl's own
preprocessing/BL-norm code from `3_anxolotl/` via an explicit `sys.path`
addition rather than duplicating it.

The folder's earlier scripts (`cross_dataset_v4.py`, `cross_dataset_blnorm.py`,
`cross_dataset_dann.py`) are archived in `archive/` — they use a
pre-2026-07-19-leak-fix normalisation and a non-canonical 712-window
target (they raise a `RuntimeError` if the WESAD∩Anxolotl intersection
isn't exactly 40 features, to catch an accidental schema swap, but that
40-feature training space is not Table 4.12's 55-feature evaluation
target) — they do not reproduce Table 4.12's current numbers.

Check `results_master.csv`'s `feature_set`/`source_file` columns for exactly
which schema backs any individual result.

### AutoGluon results are not bit-exact reproducible

`1_wesad/classical/wesad_autogluon_rerun_fixed.py` (the canonical AutoGluon
source, thesis Table 4.9) calls `TabularPredictor.fit()` without setting a
seed — AutoGluon exposes no equivalent of `random_state` for this.
Re-running the identical script on the identical
`processed_data_137feat_snapshot.pkl` gives Macro-F1 within roughly
**±0.01–0.02** of a previous run (e.g. 0.909 vs. 0.892 on two different
reruns of the same snapshot) — this is expected AutoGluon variance, not
evidence of a schema or environment problem. Run it with a Python
environment that has the `autogluon` package installed — the base Python
environment used elsewhere in this repo does not have it.

## 3. WDD — "Wearable Device dataset during stress and exercise" (public, via Kaggle)

**`2_cross_dataset/wearable-device-dataset.ipynb` is the preprocessing script
for WDD** — the equivalent of `1_wesad/wesad_preprocessing.py` or
`3_anxolotl/anxolotl_preprocessing.py`, just as a notebook instead of a `.py`
file. It reads the raw per-subject ACC/EDA/TEMP/BVP CSVs, filters the
signals, builds the tabular feature set (`build_features_v2`) and the DL
sequence version (`build_sequences`), and saves both
`processed_data/wdd/processed_data.pkl` and
`processed_data/wdd/processed_data_sequences.pkl` — the two files every WDD
script/notebook downstream reads (most via `common.py::load_wdd()`, a few
load the pickle directly). It was run on Kaggle against this input path:
```
/kaggle/input/datasets/protobioengineering/wearable-device-dataset-during-stress-and-exercise/
    wearable-device-dataset-from-induced-stress-and-structured-exercise-sessions-1.0.1/
    Wearable_Dataset/STRESS/{subject}/{tags,ACC,EDA,TEMP,BVP}.csv
```
i.e. Kaggle dataset `protobioengineering/wearable-device-dataset-during-stress-and-exercise`
— confirm the exact slug on kaggle.com before downloading, since this is
inferred from the hardcoded path in the notebook, not independently verified.

**This dataset is never vendored in the repo.** The notebook must be re-run
(on Kaggle, or locally after adjusting `base_path`) to regenerate
`processed_data/wdd/processed_data.pkl` and
`processed_data/wdd/processed_data_sequences.pkl` — there is currently no
script that does this outside the notebook.

## 4. External sibling directory dependency (WESAD sequence data) — reproducibility gap

The deep-learning WESAD scripts (`scripts/wesad_1dcnn.py`, `wesad_cnngru.py`,
`wesad_rnn.py`, `wesad_transformer.py`, `wesad_mamba.py`, `wesad_dann.py`,
via `scripts/common.py::load_wesad_seq()`) load **sequence-windowed** WESAD
data from:
```
WESAD_SEQ_PATH  (env var, required — no default; scripts/common.py raises
  RuntimeError if unset when load_wesad_seq() is called)
```
On this machine it currently points at `.../Tese/DANN/wesad/processed_data_sequences.pkl`.
This file lives in a **separate sibling project** (`.../Tese/DANN/`), not in
this repo, and there is no script in `anxolotl/1_wesad/` that produces it —
`1_wesad/wesad_preprocessing.py` only builds the *tabular* (statistical
feature) version. **Anyone reproducing the DL scripts elsewhere must either
also have the `DANN` sibling project, or write their own equivalent
sequence-windowing script and point `WESAD_SEQ_PATH` at its output.** This is
flagged again in the reproducibility risks list in README.md.

## 5. Regenerating `processed_data/*.pkl` from raw data

Once the raw data above is in place:

```bash
# WESAD → processed_data/wesad/processed_data.pkl (NEW schema, 130 feat)
python 1_wesad/wesad_preprocessing.py
```

NOTE: this command's output is the source for thesis Sections 4.3 and 4.13
(filtered downstream to the 5-channel `acc_wrist, hr, ibi, rmssd, sdnn`
subset, 55 feat) — it does NOT reproduce Sections 4.2 or 4.4, which need
the *old* 137-feat schema instead. Those two need
`processed_data/wesad_archive/processed_data_137feat_snapshot.pkl` (already
in this repo, frozen — the code that originally generated it does not
survive here). See "WESAD feature schemas" above before assuming this one
command reproduces everything WESAD-related in the thesis.

```bash
# Anxolotl → processed_data/anxolotl/processed_data_anxolotl.pkl (+ _seq.pkl)
python 3_anxolotl/anxolotl_preprocessing.py sessions/ processed_data/anxolotl/

# WDD → processed_data/wdd/processed_data.pkl
# (run 2_cross_dataset/wearable-device-dataset.ipynb end-to-end; no .py equivalent exists)
```

See README.md for the full pipeline (feature extraction → BL-norm → model
training → evaluation) that consumes these pickles.

For exact feature/channel counts, unused byproduct configs, the §4.4
40-vs-55 detail, and the canonical source per model for Tables 4.5/4.9, see
the internal audit log (not part of this public repository) — this file
stays scoped to "how to obtain and use the data."
